# چطور بیلد بگیریم (روی هر سیستمی)

پیش‌نیاز: .NET 10 SDK، PowerShell 7 (`pwsh`) و Git. پروژه را کلون کنید و روی شاخه‌ی کاری (`slice-14/ai-assistant`) بمانید. هر چیزی که می‌سازید زیر `artifacts/` می‌رود و در git نیست.

## ساخت همه‌چیز (دستور اصلی)

```
pwsh tools/publish.ps1
```

این یک دستور چهار خروجی می‌سازد:

| خروجی | مسیر | برای چه کسی |
|---|---|---|
| نسخه‌ی مازستایی | `artifacts/Mazesta-Admin/Mazesta-Admin.exe` | خود شرکت (شماره‌ی سرویس، ارسال به سایت) |
| نسخه‌ی کاربر | `artifacts/Mazesta-Client/Mazesta.exe` | کاربران، بدون ویژگی‌های شرکت (پوشه‌ی بدون نصب) |
| **نصب‌کننده‌ی کاربر** | `artifacts/Mazesta-Setup/MazestaTestSetup.exe` | **همین فایل را به کاربر بدهید**: نصب با Start menu، میان‌بر دسکتاپ و ثبت در Installed apps؛ حذف از `Mazesta.exe --uninstall` |
| **برنامه‌ی منشی** | `artifacts/Mazesta-Print/MazestaPrint.exe` | سیستم منشی: فهرست گزارش‌های سایت با شماره‌ی سرویس و چاپ خلاصه (فایل جداگانه، نیازی به برنامه‌ی اصلی ندارد) |

- نصب‌کننده، نسخه‌ی کاربر (`Mazesta-Client`) را بدون پوشه‌ی `Data` داخل خودش می‌گذارد، پس همیشه **بعد از** ساخت نسخه‌ی کاربر ساخته می‌شود (خود اسکریپت این ترتیب را رعایت می‌کند).
- فقط یکی از نسخه‌ها: `pwsh tools/publish.ps1 -Only Mazesta` یا `-Only Client` (با `-Only Mazesta` نصب‌کننده ساخته نمی‌شود).
- اسکریپت قبل از هر کاری نگاه می‌کند برنامه یا `MazestaTray` از همان پوشه در حال اجرا نباشد و اگر بود **بدون تغییر** متوقف می‌شود: اول ببندیدشان (نوار کنار ساعت هم). اگر `MazestaPrint` باز باشد فقط همان بازسازی نمی‌شود (هشدار می‌دهد) و بقیه ساخته می‌شوند.
- پوشه‌ی `Data` (تنظیمات، گزارش‌ها، تاریخچه، کلید برنامه‌ی منشی) هرگز پاک نمی‌شود؛ پیش از هر ساخت یک نسخه‌ی پشتیبان بیرون از ریپو در `../Mazesta-Data-Backups` گرفته می‌شود. پوشه را دستی پاک نکنید.
- اندازه‌ها: نصب‌کننده حدود ۱۵۵ مگابایت (همان اندازه‌ی zip برنامه‌ای که داخلش است؛ خود نصب‌کننده چند صد کیلوبایت است، چون با ‎.NET Framework خود ویندوز ۱۰ و ۱۱ اجرا می‌شود و runtime جدا همراه ندارد)، برنامه‌ی منشی حدود ۵۰ مگابایت.

## نسخه‌ی انتشار برای سایت (به‌روزرسانی خودکار کاربران)

نسخه‌ی کاربر برای انتشار با `tools/publish-release.ps1` (خروجی `artifacts/Mazesta-Release`) و `tools/release.ps1 -App …` ساخته و امضا می‌شود؛ جزئیات و کلید امضا در [UPDATES.md](UPDATES.md).

## افزونه‌ی سایت

افزونه یک فایل است: `site/mazesta-connect/mazesta-connect.php`. برای آپلود، آن را داخل پوشه‌ای به نام `mazesta-connect` زیپ کنید (زیپ باید `mazesta-connect/mazesta-connect.php` را داشته باشد) و در وردپرس نصب کنید؛ نسخه را هم در هدر فایل و هم در `const VERSION` بالا ببرید.

## بعد از ساخت

```
dotnet build Mazesta.sln -c Release
dotnet test  Mazesta.sln -c Release --no-build --filter "Category!=Hardware"
```

(هشدار = خطا؛ تست‌های `Category=Hardware` فقط روی سخت‌افزار واقعی.) هر خروجی‌ای که روی سیستم دیگری ساخته می‌شود همان چهار فایل بالاست؛ توضیح دیگری لازم نیست.
